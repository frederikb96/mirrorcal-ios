# MirrorCal iOS

[![CI](https://github.com/frederikb96/mirrorcal-ios/actions/workflows/free-checks.yml/badge.svg)](https://github.com/frederikb96/mirrorcal-ios/actions/workflows/free-checks.yml)
[![Release](https://img.shields.io/github/v/release/frederikb96/mirrorcal-ios)](https://github.com/frederikb96/mirrorcal-ios/releases)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT)

A native iPhone app that one-way mirrors events from a work Exchange calendar into a private
Nextcloud (CalDAV) calendar, so a phone's personal calendar shows work commitments without either
calendar account needing to know about the other. The source calendar is never written to — the
sync direction is structural, not a setting.

This is a port of an [Android app](https://github.com/frederikb96/mirrorcal) doing the same job,
re-derived rather than translated: iOS has different background-execution rules, and the sync
design accounts for that from the start rather than working around it after the fact.

## How it is arranged, and why

Almost everything lives in `MirrorCalKit`, a local Swift package. **The package builds and tests
on Linux; the app target compiles only on macOS.** That split is the whole architecture: package
code is proven in seconds for free, app-target code is proven only when a macOS runner runs. So
the views stay thin, and anything a unit test could catch lives in the package.

| Path | What |
|---|---|
| `MirrorCalKit/` | the logic and its tests |
| `MirrorCal/` | app target: views, and anything needing an Apple framework. A synchronized folder, so new files need no project edit |
| `MirrorCal.xcodeproj` | written by hand, small, not regenerated by any tool |
| `Config/` | xcconfig; `MARKETING_VERSION` comes from the git tag via CI |
| `Tooling/` | checks that catch macOS-only compile errors without a Mac |

## Building

The package needs only a Swift 6.2 toolchain, on any platform:

```
swift build --package-path MirrorCalKit --build-tests
swift test  --package-path MirrorCalKit --skip-build
```

The app target needs Xcode; CI builds it on a macOS runner.

## CI

| Workflow | Answers | Runner |
|---|---|---|
| `Free checks` | compiles, tests pass, formatted | Linux |
| `Mac` | does it actually run — boots it, screenshots it, queries its debug endpoint | macOS |

`Mac` publishes the screenshot and the device log as artifacts, because an automated check can
pass while the screen renders nothing.

## Push sidecar (optional)

`push-sidecar/` and `charts/mirrorcal-push/` are an optional, self-hosted piece: a small Go
service plus a Helm chart, both independent of the app and versioned/released separately, that
sends scheduled silent pushes to wake the app in the background — the strongest lever iOS gives
an app that isn't in the foreground. Anyone with a Kubernetes cluster and their own Apple
developer account can install it against their own copy of the app; see each directory's own
README for what it does and how to run it.
